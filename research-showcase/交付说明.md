# 渝研：两个产业案例的研究与展示交付

## 先打开什么

1. `渝研_交互研究页面.html`：下载后直接用浏览器打开，无需安装、登录或输入问题。它已内嵌数据及完整PDF。
2. `dist/渝研_产业经营研究报告.pdf`：9页独立阅读报告，第一页给问题、结论与建议，不需要先操作页面。
3. `dist/`：可以单独部署到静态网站的目录；入口为 `index.html`。

## 这次实际改变了什么

- 主案例从120户跨行业动作评分收窄为三个榨菜产业链客户原型。分别明确经营任务、付款时点、核查材料、工时组成与停止条件，不再用未校准的收益系数给出“利润最优”排名。
- 汽车案例改为比较现金、三个月银行承兑汇票、次日贴现及现金晚14天。展示取得票据之前与之后的不同资金问题。
- 新模拟数据独立于旧版49万元、38/52天案例。它不是对旧数据的修正，也不是经营绩效变化；本展示不混用两个版本。
- 页面没有自由输入框。经营情景直接切换；汽车情景需要先确认对象、金额、现金日期和条件，再显示对应结果。
- 所有关键任务内容直接展示，不必展开才能知道具体做什么。
- AI责任单独解释。本展示不调用在线模型，不把预设文字伪装成实时模型日志。

## 三分钟演示

0:00–0:30：首页说明两项决策：银行先服务谁，企业何时有现金。告诉观众公开资料与模拟数据的边界。

0:30–1:30：看三张客户卡。经销商36万元缺口小于合作社90万元，但更早付款。看18小时安排，再切换“经销订单存疑”，说明真实经营判断会被新证据推翻。

1:30–2:30：打开汽车案例。确认期初35万元已经包括24万元预付款。选择三个月票据，核对参数后确认；峰值56万元不变，负余额期由94天变为185天。

2:30–3:00：选择贴现成功情景。95天、费用6,627.95元；它解决收票之后的占用，却不解决1月采购付款。最后打开报告与依据，让观众可以独立查证。

## 发布到现有GitHub Pages

`dist/`完全静态，不需要Python API、数据库或Qwen密钥。部署时应把本目录作为唯一对外展示入口，避免首页仍引用旧120户评分与49万元案例。

若沿用现有Vite项目，可把本目录复制到 `site/public/studies/`，先通过 `/yuyan-bank-research/studies/index.html` 检查真实页面。通过后将原首页入口指向该地址；无需更改原后端业务代码。不要直接把旧Vite构建输出与本目录混合覆盖后宣称发布完成。

## 复算与重建

Python模型只使用标准库：

```bash
python3 model.py
python3 -m unittest test_model -v
```

报告构建依赖ReportLab与Noto Sans SC字体。将有合法授权的常规字体放到 `fonts/NotoSansSC-Regular.ttf` 后运行：

```bash
python3 render_report.py
python3 build_page.py
```

网页DOM检查需要Node和happy-dom。交付包中不包含任何在线账户、API密钥、系统提示词或旧运行轨迹。

## 关键边界

模拟企业不是涪陵榨菜集团或任何真实企业的账户映射；三个原型没有被声称为已建立的相互交易关系。2027年是前瞻情景期。

18小时、每项任务工时、收付日期、金额与2.8%贴现利率均是研究假设。缺口不是授信建议，负余额不是实际透支，期末正余额不是利润；银行经营收益没有可验证数据，因此未编造。
