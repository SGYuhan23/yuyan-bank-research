# 三分钟演示与可证实的面试表述

0:00–0:45 案例研判：输入卖方收到付款图片的问题，选择“卖方收款”，创建案件。上传项目编写图片，展示提取位置和“材料陈述”标签。执行，观察仅适用工具出现；打开原文，说明截图不证明到账。

0:45–1:20 修改人工转录或角色：版本增加，旧结果不能审核。继续执行，审核、驳回或修订当前建议，再导出带版本及审核记录的案件。操作者名称只是本地记录。

1:20–2:00 培训演练：开始一个账户变更情境，先询问独立电话核实。客户只释放设定事实；再复盘，显示漏问点、实际对话引用和待人工审核状态。正常变更不因账户变化就被定性诈骗。

2:00–2:40 交易图实验：明确 synthetic，打开一条边。展示合法结算环也会被“有环即异常”误报，模型排序不等于真实欺诈概率。展示表格、邻域表示和结构移除结果；新结构测试成绩低，默认保留简单模型。

2:40–3:00 失败例：未知角色触发澄清；检索不可用明确失败。展示开发失败记录与同底模强基线，不能只挑演示输出说优于直接模型。

面试事实框架：
- 为什么做：公开指引被套错业务对象时，原文引用也可能让错误看起来可信；工具结果和版本审核有助于暴露这类问题。
- 为什么 Agent：材料种类不同，需要不同工具，结果带案件、版本、证据和失败状态；不是因为多角色名称更先进。
- 相比直接问模型：额外价值是可追溯工具执行、修改后失效、审核持久化、培训状态隔离。答案质量是否更好须看小样本对照，不能先宣称胜出。
- 新增部分：严格数据契约、SQLite原子审核、条件LangGraph、原生OCR、受限URL检查、比较/时间线、交互训练、合成图实验、真实接口及评测。
- 失败案例：规划器曾重复请求已执行工具、索要并不存在的附件；证据别名与ID混淆；语义复盘曾引用错误轮次。错误记录保留，修复不是模型通用正确性保证。
- 个人角色、学校合作、项目日期、银行采用情况须由本人确认；本文不替本人编写归属或业务收益。
